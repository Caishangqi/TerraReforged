# TerraReforged

TerraReforged is a fork of [Terra](https://github.com/PolyhedralDev/Terra) brought up to a current
Minecraft version. Upstream Terra targets 1.21.10. This tree ports its Paper side to Minecraft 26.2,
the release after 1.21.11: the version numbering went 1.21.11, then 26.1, then 26.2, so there is no
1.26.2 artifact to look for.

Terra generates worlds from configuration rather than from code. A config pack describes biomes,
terrain, ore, flora, structures and the noise behind them in YAML and TerraScript, and the generator
reads that at runtime. The API, the addon loader, the core addons and the pack format are Terra's, and
this fork does not change them.

What a pack or an existing world depends on is unchanged from Terra: the command names (`/packs`,
`/addons`, `/structures`, `/search`, `/profiler`) and their `terra.*` permission nodes, the `terra:`
biome namespace, the `terra` addon id and the `com.dfsek.terra` packages. A pack written for Terra loads
here, and a world generated by Terra keeps its biomes.

## Supported platforms

Paper 26.2 and Purpur 26.2. Both are verified against pinned builds: Paper 26.2 build 129, which is the
build the Paperweight Dev Bundle is pinned to, and Purpur 26.2 build 2633.

Plain Bukkit and Spigot are out of scope. The Bukkit modules compile against the Paper API, Paperweight
Userdev, the Paper Registry API, the Paper Region Scheduler and Paper-internal NMS, none of which Spigot
has.

The upstream Fabric, Forge, Quilt, Minestom, Allay, Sponge and CLI sources are still in `platforms/`,
but `settings.gradle.kts` does not include them, so they are not compiled, not tested and not shipped.
They are kept for reference while the Paper port is the active work. Use upstream Terra for those
platforms.

## Layout

| Directory | Contents |
| --- | --- |
| `common/api` | The platform-neutral API. |
| `common/implementation` | The platform-neutral implementation: config packs, registries, the profiler, the addon loader. |
| `common/addons` | The core addons. Config parsing, TerraScript, noise and most generation algorithms live here and are independent of the Minecraft version. |
| `platforms/bukkit/common` | The Paper API boundary: plugin lifecycle, commands, events, wrappers and the Bukkit `ChunkGenerator`. Its `hooks` package holds the Multiverse and Oraxen integrations. |
| `platforms/bukkit/nms` | One module per set of Minecraft versions that share their internals. `v26_2` is the only one. |
| `platforms/bukkit` | The distribution module that shades the above into one jar. |
| `buildSrc` | Shared Gradle configuration. Bukkit and Minecraft versions are in `Versions.kt`. |

Supporting a new Minecraft version is a module directory under `platforms/bukkit/nms` and an entry in
`NMSInitializer.BINDINGS`. Nothing lists the modules by name.

## Building

Java 25 is required. The Gradle wrapper is 9.8.0 and resolves its own toolchain.

```bash
./gradlew :platforms:bukkit:build          # gradlew.bat on Windows
```

This produces `platforms/bukkit/build/libs/TerraReforged-bukkit-<version>-shaded.jar`. That shaded jar
is the one to install: the core addons are packaged inside it and are written to the data folder on
first start.

`./gradlew test` runs the unit tests for the whole included tree.

## Installing

Drop the shaded jar into a Paper or Purpur 26.2 server's `plugins/` directory and start the server. The
plugin loads at `STARTUP`, because it supplies the world generator and has to exist before worlds load.

Name a pack in `bukkit.yml` to have a world generated by it:

```yaml
worlds:
  world:
    generator: TerraReforged:<PACK>
```

A world folder remembers the generator it was created with, so delete the world before changing its
pack. Mixing the two produces a world that is neither.

For development, `./gradlew :platforms:bukkit:runServer` starts a Paper server under
`platforms/bukkit/run` with the plugin already installed.

## Configuration

The data folder is `plugins/TerraReforged`.

| File | Purpose |
| --- | --- |
| `config.yml` | Core options: debug switches, cache sizes, biome search resolution. |
| `lang.yml` | Console message templates. MiniMessage, so hex colours, gradients and legacy `&a` codes all work. Deleting a value falls back to the built-in text. |
| `packs/` | Config packs, as zips or directories. |
| `addons/` | Addon jars. Rewritten from the plugin jar on every start. |

If you carry a `plugins/Terra` folder over from upstream Terra, delete its `addons/` directory first.
Those jars are named `Terra-*.jar` and the current ones are `TerraReforged-*.jar`, and the dumper prunes
by file name, so both sets would survive and every addon would load twice. The plugin warns and names
any addon id that loads more than once.

## Plugin integrations

`Multiverse-Core` can create a world from a pack: `/mv create <name> NORMAL -g TerraReforged:<PACK>`.

`Oraxen` custom blocks can be named in a pack wherever a block is *placed*, as `oraxen:<id>`, using the
same id format Oraxen documents for Iris. The noteblock, stringblock and chorus mechanics are covered.
Shaped blocks and furniture are not, because neither can be read back out of block data. Terra loads its
packs a few seconds before Oraxen is enabled, so an `oraxen:` id is resolved on first use rather than at
load, and a world listed in `bukkit.yml` generates its spawn area before Oraxen exists and therefore
cannot use these blocks at all.

## Contributing

Issues and pull requests are welcome. Keep version-specific code inside the NMS adapter under
`platforms/bukkit/nms`, and keep Paper types out of `common/`.

A change to world generation needs a result from a running server rather than a passing compile. The
seam between `platforms/bukkit/common` and an NMS adapter is a class name resolved at runtime, not a
type, so a renamed adapter package or a wrong version binding compiles cleanly and fails at server
start. Read the saved region files to confirm what was generated; a log line saying the generator was
installed is not the same as chunks containing the pack's blocks.
